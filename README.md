# 《小兵传奇》星际战争游戏 — NLP 课程项目

NLP 课程 project，方向是 AI + gaming。做一个基于玄雨《小兵传奇》设定的单机剧情游戏：战略层走星图、关系网、剧情分支，战斗层是参照《战舰世界》手感的实时 3D 遭遇战。技术栈 Unity + Blender，目前处于设计与原型阶段，尚未进入正式开发。

## 打开原型

`proposal/原型设计/prototype.html` 是单文件，直接用浏览器打开即可，无需构建。

也可以起本地服务器：

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory proposal/原型设计
```

原型有五个视图（星图 / 关系网 / 作战 / 资源 / 剧情）。两个值得试的交互：

- 点击右上角阵营徽章，循环切换联邦 / 银鹰 / 家族，观察关系网和资源可见度如何随配置变化——这是"同一套系统 + 配置驱动差异"的直观演示。
- 切到作战页，点击战场移动准星开火，看弹道轨迹与命中反馈；WASD 改航速舵角，空格齐射；右侧四个分队可下指令。

原型只演示信息架构与交互流程，不接真实规则引擎，也不做真正的 3D 渲染。

## 设定来源

所有游戏设定的原始出处是 `参考资料/小兵传奇.txt`。三份分析文档按主题把它拆开，每条结论都附了章号，可直接回原文核对。

章号指文件行首"第 N 章"的**总编号**。小说正文里卷内小节标题会重置（比如出现多个"第三章"），用总编号定位才不会混淆。

## 设计要点

**三阵营共享底层。** 联邦、银鹰、家族三套路线的关系网、作战体系、星际地图是公共模块，阵营差异由配置表驱动，不写三套逻辑。成长路线同构：家族靠资源膨胀，另两条靠军功；前期联邦 / 银鹰的资源由高层代管，玩家专注作战，后期晋升高层后汇合到同一套经济系统。

**战斗层与战略层窄接口。** 战略层传入敌我编成、战场类型、剧情目标；战斗层回传战损、军功、耗时、剧情标记。战斗内部怎么跑，战略层不关心。这条边界让战斗模块可以独立砍功能而不牵连剧情和关系网。

**战斗群映射。** 战舰世界里一艘舰的主炮 / 副炮 / 侦察机 / 舰载机，对应小说的主舰 / 僚舰 / 巡逻舰 / 副舰，做成四个固定分队槽位。玩家直接驾驶主舰，其余三支用指令调度，既有舰队层次感又不用做逐艘操控的 RTS。

## 当前进度

已完成：小说设定梳理、故事线与作战体系分析、初步设计、中英文 proposal、系统架构设计（实时 3D 版）、可点击原型、
可编译的 12 包 22 程序集骨架、三维真实战斗仿真（运动/弹道/扫掠命中/敌舰 AI/胜负，无 Unity 可跑）、
舰体能源系统（推进·转向·开火三路耗电、全舰记账、耗尽熄火与滞回恢复）、目标锁定与提前量解算、
护盾与装甲结算（绑定舰体的三面减伤、过载缓冲池、破盾失效、抗伤耗电、延迟回充）、
舰船配置加载（`content/ships/*.json` → 运行时属性，代码里不再留数值副本，非法值直接报错不被截断）、
炮座化（每舰 2–4 门，装填/射界/装药各自独立，不建模炮塔转速，HUD 可显示「X/Y 就位」）、
逐座表现接口（`ShipSnapshot.Turrets` 给每座装填进度与瞄准方向，`BattleEvent.Shot` 给炮座/弹丸/出膛点/方向，
表现层不解析事件文案、不重算提前量）。

最近一轮审查修掉了四处会影响真实战斗的错：敌舰 AI 意图排在能源结算之前（否则它转向不扣电）、
熄火后为「不会执行的推力」继续扣电（导致永锁）、射程外开火白扣电、测试自己没设血量与命令时序。
同时堵掉一处静默降级：配置里写 `channel: beam` 会得到「有飞行时间的激光」，现在解析器直接拒绝，
`DamageChannel` 只负责挑防御分支、不负责挑投送方式，光束投送排到 Phase 1.5。

测试与仿真现在**真在跑**：`tools/SmokeTests` 34 个场景块 / 134 条断言全绿，
`.github/workflows/smoke.yml` 在 ubuntu 上自动执行同一套检查（编译 22 个工程 + 冒烟 + 300 s 仿真）。
跑通的第一件事是把一个旧结论推翻了：等效二维模型说"2v3 六个种子 69–129 s 全胜"，
真实引擎跑出来是三个种子各 300 s **零击沉**——双方以 20–32 km/s 交汇，一次开窗只有 3–4 s，
装填却要 3.2–6 s，打完就飞过去。所以下一步的瓶颈是运动与火控（T10 炮塔化、T12 AI 绕后），
而不是护盾或伤害。细节见 `docs/phase1-tasks.md` 第 6 节。

下一步：按 `docs/vertical-slice-plan.md` 做最小闭环——Unity 侧场景与输入层、任务日志运行时、星图两节点 UI。
接 HUD 前先读 `docs/combat-open-items.md`：`CanFire` 不含能源、装填时长要在开火时定死、
瞄准方向与弹丸世界运动方向的关系待选，这三条都会影响表现层怎么写。
战斗数值验证：`dotnet run --project tools/CombatSimCli -- --seed N`。
