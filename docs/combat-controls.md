# 战斗逻辑与操控

状态：2026-11-25。本文描述**代码里现在真实是什么**，以及设计上要往哪走。
三条线必须分清，混起来调参会出错：

| 标记 | 含义 |
| --- | --- |
| **[已实现]** | 代码里就是这个行为，改文档不改变游戏 |
| **[未实现]** | 设计已定，代码还没有（多数在 B 的 Unity 外壳与配置加载器） |
| **[待定]** | 还没有定论，先按默认值跑 |

武器与防御的未来方案见 `docs/weapon-defense-design.md`（v0.4）。本文只描述战斗层；
两者冲突时以武器设计稿为准，并回来修这里。

## 0. 操控复杂度：核心 5 个键，其余分档

武器设计稿早期写过"能接受 3–5 个按键的玩家"，那句说的是**核心操作**，不是全部按键。
实际映射有 10 个输入源，所以必须分档，否则"键位太多"会变成"玩家一个都不按"：

| 档 | 按键 | 何时必须用 | 能否全程不用 |
| --- | --- | --- | --- |
| 核心 | W/S 俯仰、A/D 偏航、空格推力档 | 每分钟都在用 | 不能 |
| 常用 | 左键开火、Tab 锁定 | 每个节拍都用 | 不能 |
| 辅助 | Q/E 滚转、F 飞控、1/2/3 能源档 | 需要调整姿态或分配时 | 短期可以 |
| 高级 | Shift 反推、切武器通道、护航命令 | 特定局面 | 可以全程不用 |

设计上要求：**新玩家只学核心 + 常用五键就能打完一局**，辅助与高级是效率工具而不是前提。
姿态稳定默认开启（`FlightAssist = true`），关掉它才需要滚转与手动配平。

## 1. 坐标、单位、时钟

| 项 | 约定 |
| --- | --- |
| 坐标系 | 右手系，X 右、Y 上、Z 前；**舰体局部 +Z 为舰首** |
| 长度 | km（战场尺度 0–320 km） |
| 速度 | km/s（主力舰 20–32，投射体 220–300） |
| 角速度 | 度/秒；角加速度 度/秒² |
| 姿态 | 内部四元数，导出欧拉角，约定与 Unity `Quaternion.Euler(pitch, yaw, roll)` 一致 |
| 步长 | 固定 1/30 s，`BattleStartSpec.FixedStep` |

这是"贴脸距离"的太空战：320 km 只相当于光走 1 ms 的路程，所以投射体 0.7–1.4 s 的飞行时间纯粹是玩法参数，不是物理推导。[已实现]

## 2. 操控映射

输入层尚未落地（属于 Unity 外壳），下表是已定的映射，**[未实现]**。战斗侧的命令契约已经就位，接线时只做"按键 → 命令"的转换。

| 按键 | 命令字段 | 效果 | 状态 |
| --- | --- | --- | --- |
| W / S | `HelmCommand.Pitch` | 抬头 / 低头，给的是角加速度输入 | 已定 |
| A / D | `HelmCommand.Yaw` | 左 / 右偏航 | 已定 |
| Q / E | `HelmCommand.Roll` | 滚转 | 已定 |
| 空格 | `HelmCommand.Thrust` | 推力档位循环：0 → 1/3 → 2/3 → 1 → 0 | [待定]，档位数未定 |
| Shift | `HelmCommand.Thrust = -0.5` | 反推（喷口效率低，耗电 ×1.4） | [待定] |
| F | `HelmCommand.FlightAssist` | 飞控开关，sticky（记住最近一次） | 已定 |
| 鼠标 | `AimCommand` | 自由瞄准点（世界坐标） | 已定 |
| 左键 | `FireCommand` | 请求开火，走装填与能源检查 | 已定 |
| Tab | `LockTargetCommand` | 锁定光标下的敌舰，再按一次解除 | 已定 |
| 1 / 2 / 3 | `PowerAllocationCommand` | 导航 / 均衡 / 交战三档预置 | 已定 |

三条容易被误解的规则：

- **角速度输入是"按住有效"**，每 tick 清零；**推力档位与飞控开关是 sticky**，不按住也保持。所以"松手还带一下"是设计，不是延迟。[已实现]
- **档位控的是加速度，不是速度。** HUD 必须同时显示档位与当前加速度，否则玩家会以为档位坏了。[已实现]
- **反推不是刹车。** 真空里没有阻力，反推只是往反方向加速；要停住得自己算半个行程。[已实现]

### 2.1 鼠标怎么在三维里指定一个点

屏幕上的一个像素没法唯一确定世界坐标——这是三维瞄准的老问题，必须定死规则，否则实现者会各自发明一套。

| 情形 | 规则 | 理由 |
| --- | --- | --- |
| 光标压在某艘舰上 | 射线与舰体包围球求交，取最近命中点 | 打舰是绝大多数情况 |
| 光标在空白处 | 射线与"距相机 200 km 的过场平面"求交，得到空间中的一个点 | 允许打提前量位置（预判射击），也允许误瞄，这就是操作成本 |
| 已锁定目标 | 鼠标改控**相对锁定点的角偏移**（±3°），不再决定世界点 | 锁定的意义就是"不用自己找点"，此时鼠标是微调工具 |

准星必须三种形态，随武器通道切换（这是 P5 的硬要求，不是美术偏好）：

| 通道 | 准星 | 显示什么 |
| --- | --- | --- |
| 光束 | 一个固定环，贴炮塔指向 | 蓄力进度用环的内圈填充 |
| 投射体 | 提前量点 + 一条虚线连到目标当前位置 | 虚线长度 ≈ 飞行时间，玩家能读出"他还能跑多远" |
| 未锁定 | 中心点 + 距离刻度 | 距离刻度让 `v ≤ a_max/ω` 那个判断有个可读依据（6.5） |

### 2.2 护航命令（包夹的前置条件）

玩家必须能指挥护航舰，否则"角分离包夹"只能靠 AI 碰巧站位，H2 验不了。

| 命令 | 字段 | 效果 |
| --- | --- | --- |
| `EscortMoveTo` | `ShipId, X, Y, Z` | 护航舰飞向指定点并停在那（不追击） |
| `EscortAttack` | `ShipId, TargetId` | 护航舰攻击指定目标；TargetId 为空则回护卫队形 |

选择方式：`4` / `5` 选中护航舰 1 / 2，右键下 `EscortMoveTo`，左键下 `EscortAttack`。
两条都是 **[未实现]**，属 T17。**没有它，两舰包夹就只能靠 AI 自己走位**——那样测出来的"包夹收益"是 AI 的收益，不是玩家的。

## 3. 机动

### 3.1 推力与速度

```text
accel = forward × MaxThrust × ThrustSetpoint × dt
forward = 姿态四元数旋转局部 (0,0,1)      // 恒沿舰首，不跟随速度方向
v += accel
if |v| > MaxSpeedKps → v 等比缩回（只改大小，不改方向）
if 已到限速且推力同向 → 不再施力         // 避免「满档推不动」
```

推力与速度完全解耦：侧滑、倒飞、被打歪之后照样沿舰首加速。这是无阻力真空 + 主推进的必然结果，不是简化。[已实现]

### 3.2 转向

```text
u = |输入|>0 ? 输入 : (飞控 ? -ω/(α·dt) : 0)
ω = clamp(ω + u·α·dt, ±MaxRate)
```

无输入且开飞控时，飞控给一个反向角加速度，让 ω 按同一条积分公式线性降到 0；`|ω| ≤ α·dt` 时该式恰好落在 0 且不越过，所以是"收力"不是"阶跃"。死区 0.5 °/s。三轴独立判断，按住偏航时俯仰的残余转速仍在反喷。[已实现]

`FlightAssist = false` 时 `u = 0`，角速度永不衰减，用来演示纯牛顿。滚转回平是二级开关，**默认关闭**（太空没有"上"）。[已实现]

### 3.3 三舰手感（当前配置算出来的）

| 指标 | 巡逻艇 | 驱逐舰 | 巡洋舰 |
| --- | --- | --- | --- |
| 最大推力 | 4.0 km/s² | 3.5 | 2.5 |
| 限速 | 32 km/s | 28 | 20 |
| 0 → 限速 | 8.0 s | 8.0 s | 8.0 s |
| 偏航 180°（满转） | 4.0 s | 5.6 s | 9.0 s |
| 满转松键停住 | 0.25 s | 0.25 s | 0.25 s |
| 松键余转角度 | 5.6° | 4.0° | 2.5° |
| 滚转 180° | 2.2 s | 3.1 s | 5.0 s |

三个"8.0 s"不是设计，是初值恰好凑出来的（限速 ÷ 推力）。调手感时注意别把它当成基准。

## 4. 能源

### 4.1 三通道

每舰一份，三路之和必须为 1（负投入会被拒，不用归一化掩盖）。

| 预置 | 推进 | 护盾 | 武器 |
| --- | --- | --- | --- |
| 导航 | 0.50 | 0.20 | 0.30 |
| 均衡 | 0.34 | 0.33 | 0.33 |
| 交战 | 0.20 | 0.30 | 0.50 |

### 4.2 四路耗电

```text
eff   = 0.55 + 1.35 × Propulsion              // 均衡 ≈ 1.0
drain = PropulsionDrain × |thrust| / eff       // 反推 ×1.4
      + TurnDrain × (|pitch|+|yaw|+|roll|)/3 / eff
      + ShieldDrain × (Shield × 3)             // 只在护盾未满时计
开火另扣 WeaponDrainPerShot，扣不出来就打不出去
Energy += (Regen − drain) × dt  → 夹到 [0, Capacity]
```

护盾回充也在这里：`ShieldRegenPerSec × (Shield × 3) × 供电系数`，能量低于容量 5% 时线性掉到 0。[已实现]

### 4.3 耗尽与恢复（滞回）

```text
Energy == 0                    → PropulsionLocked = true，推力强制归零，事件 PowerEmpty
Energy ≥ Capacity × Restart    → 解锁，事件 PowerRestored
```

不这么做会每 tick 抖一下。滑行期间速度不变，所以熄火罚的是**机动**不是航速。[已实现]

### 4.4 能源模拟范围（全舰记账，2026-11-26 已落地）

**现状**：所有舰都记账——护航舰、敌舰、玩家的主舰一视同仁，各自一份储能、各自会熄火。
`SimulatesEnergy` 开关已随 T06 删除，`PowerSystem` / `TryConsumeShot` / `ShieldSystem.RegenRate` /
`DamageResolver` 里都不再有「该舰不参与模拟」的分支。[已实现]

之前的风险是真实存在的，记在这里免得有人再把简化加回来：敌舰等于无限电时可以永远满推满转，
这样测出来的"玩家被压制"有一部分是假象；抗伤耗电对不记账的舰不生效，等于**敌舰的护盾永远不因挨打而变薄**。

| 场景 | 规则 |
| --- | --- |
| 战斗运行时 | 所有舰记账（已实现） |
| 平衡测试 | 必须对称：敌我同参数同规则，否则结论无效 |
| 性能兜底 | 若将来真要做简化账本（只记推进与射击），**必须在快照里标出来**，且该组数据不得用于平衡结论 |

另外一条已经变了的事实：护航舰血量不再写死 200，而是按 `DefinitionId` 读配置
（假舰队里是 `ship.d_destroyer`，300 血）。此前"护航舰比配置硬 67%"的结论作废。

### 4.5 电账

| 舰型 | 满推净耗 | 满推见底 | 满推+转向净耗 | 满推+转向见底 |
| --- | --- | --- | --- | --- |
| 巡逻艇 | 0.6/s | 133 s | 1.1/s | 73 s |
| 驱逐舰 | 0.8/s | 175 s | 1.5/s | 93 s |
| 巡洋舰 | 1.2/s | 100 s | 2.0/s | 60 s |

（净耗 = 耗电 − 再生。满推+转向按三轴输入平均 1.0 算。）

护盾**不在这张表里**：它没有"每秒充盾耗电"这一项，抗伤才付电（1 点被挡伤害 = 0.12 电），
代价随对方火力变化，写不进固定电账。所以旧版"三者同开见底"的口径已作废。

## 5. 武器（当前实现）

### 5.1 单炮模型

一艘舰只有一门逻辑炮，参数全在 `content/ships/*.json` 的 `combat` 段。

| 项 | 巡逻艇 | 驱逐舰 | 巡洋舰 |
| --- | --- | --- | --- |
| 单发伤害 | 20 | 40 | 100 |
| 射程 | 180 km | 240 | 320 |
| 弹速 | 220 km/s | 260 | 300 |
| 装填（均衡档） | 3.6 s | 5.1 | 6.8 s |
| 精度 | 0.85 | 0.88 | 0.92 |
| 散布上限 | 1.0°（实际 0.15° / 0.12° / 0.08°） | 同左 | 同左 |
| 射界 | ±15° 固定锥（绑舰首） | 同左 | 同左 |

射界那行是**当前实现**，不是目标。绑定舰体后它必须改，见 5.4。

装填实际值 = `ReloadSeconds × (1.4 − 0.8 × 武器份额)`。按三档预置算，系数分别是导航 1.16、均衡 1.14、交战 1.00——**三档之间只差 14%**，玩家基本感觉不到。×0.6 那个值要武器份额拉到 100% 才出现，现在的预置碰不到。[已实现，且是待调的缺陷]

### 5.2 一次开火的检查顺序

```text
1 装填     未完成 → 事件 NotReady
2 能源     扣不出 WeaponDrainPerShot → 事件 PowerLow
3 射程     瞄准点超过 GunRangeKm → 事件 OutOfRange
4 射界     超出 ±15° → 钳到锥边，仍然开火，事件 OutOfArc
5 散布     绕理想方向做锥形偏移，每次固定消费两个随机数
6 生成弹   世界速度 = 舰速 + 炮口方向 × 弹速
```

第 6 步的"舰速加上去"是提前量必须用相对速度的原因，见 6.2。[已实现]

### 5.3 弹道与命中

- 逐 tick 积分，累计路程超过射程即销毁。[已实现]
- 命中用**三维线段 vs 球、按两体相对位移**做扫掠：弹速 260 km/s × 1/30 s = 8.7 km/tick，舰体半径只有 0.2–0.37 km，点检测 100% 穿透。[已实现]
- 先判陨石再判舰船，取最近命中。[已实现]
- 命中只负责回答"谁打到了谁"。伤害结算全部走 `DamageResolver.ResolveHit`：判面 → 护盾 DR → 过载 → 装甲 → 结构。[已实现]
- 装甲不再死着：`beamDr` / `kineticDr` 由 `armor` 段读入，按通道取一个固定减伤（光束 0.20 / 动能 0.35）。跳弹与入射角判定仍然不做（Phase 2）。[已实现]
- 护盾不是血条：三面常驻减伤 + 过载缓冲池，详见第 5.6 节。[已实现]

### 5.4 炮塔化（Phase 1 计划，T10）

现在的 ±15° 是舰首固定锥。盾一绑舰体，"能开火"和"露正面"就变成同一件事，双方互指会僵死，所以炮塔必须松开。

**两轴，不是单轴。** 只加偏航在三维里处理不了上下方的目标——这种情况在三维遭遇战里很常见，不是边角料。

| 项 | 值 | 说明 |
| --- | --- | --- |
| 偏航轴 | 相对舰体 ±45° | 覆盖前半环 |
| 俯仰轴 | 相对舰体 ±30° | 覆盖上半个前半球 |
| 射界形状 | 上述两个范围围成的矩形截取的**圆锥区**，不是一个平面扇面 | 玩家在 HUD 上看到的是一个可动的锥 |
| 转位速率 | 60 °/s，两轴同时转，耗时取较长轴 | 0→90° 用 1.5 s |
| 开火门限 | 炮管当前指向与目标方向夹角 ≤ 3° | 没转到就开火 = 打偏，不是"钳到锥边" |
| 与舰体旋转的关系 | 炮塔角**相对舰体**保存 | 舰体转，炮塔的世界指向跟着转，不额外耗时。这是"转身保住射界"与"转身丢掉射界"的分界：转得够快时炮塔不用补 |

状态只有两个角：`TurretYawDeg` / `TurretPitchDeg`，加一个"目标角"作为 setpoint。逐 tick 按 60 °/s 逼近，两级速率限制。[未实现]

`BattleRules.ClampToArc` 保留但改用途：从"把瞄准点钳到锥边"变成"判定炮塔能否覆盖"。覆盖不了就**拒绝开火**并发事件，不再把弹打向锥边——把弹打向锥边等于让游戏替玩家做决定。

### 5.5 来袭方向怎么定义（判面的唯一约定）

判面要一个方向，而这个方向有两种叫法，互为反向。**这是最容易写错、且错了只在近距离才看得出来的一处。**

约定：**`incomingDir` = 从目标指向威胁来源的单位向量（"威胁来向"）。**

```text
cosθ = dot(incomingDir, target.Forward)
θ ≤ 45°  → 正面
45–135°  → 侧面
θ > 135° → 背面
```

命名里带 `incoming` 就是"来的方向"，代码里不必再记谁取负号。如果哪天有人把它改成"弹丸飞行方向"，正面与背面会整体互换，而正面 0.85 与背面 0.15 差 5.7 倍——只会在绕后时发现"怎么越打越硬"。

实现上还要用**相对速度**取反，不是弹丸绝对速度：舰速 30 km/s、弹速 220–300 km/s，忽略舰速会让来向偏出几度，正好落在扇区边界时正面会被算成侧面。[已实现]

**六向断言必须进 SmokeTests**（判面在舰体坐标系做，不是世界坐标）：

| 场景 | 期望 | 状态 |
| --- | --- | --- |
| 正前 0° | 正面 | 已测 |
| 正侧 90° | 侧面 | 已测 |
| 正后 180° | 背面 | 已测 |
| 正上 / 正下（±Y） | 侧面（θ = 90°） | 待补 |
| **舰体滚转 90° 后，世界 +Y 方向的来袭** | **侧面**——但若判面误用世界坐标 +Y，会得出"正面"。这一条专门抓这个错 | 待补 |

### 5.6 护盾实现（2026-11-26）

| 过载阈值 | 120 / 64 / 32（窗口 1.5 s） | 无 |

## 6. 锁定

### 6.1 规则

| 项 | 值 |
| --- | --- |
| 锁定距离 | `GunRangeKm × 1.2`（留余量，进射程前先锁上） |
| 生效 | 每 tick 用相对速度解提前量，写进快照 `AimX/Y/Z` |
| 自动解锁 | 目标死亡、跨阵营、超出锁定距离，事件 `LockLost` |
| 拒绝码 | `LOCK_OUT_OF_RANGE` / `FRIENDLY_TARGET` / `TARGET_DEAD` / `NO_SUCH_TARGET` |
| 拒绝时机 | `Submit` 阶段直接拒，不让错误命令进队列 |

锁定是纯玩家侧体验：AI 不走这条通道，自己算提前量，所以它不改变已标定的战斗节奏。[已实现]

### 6.2 提前量（一个会毁掉整场战斗的坑）

```text
rel    = targetPos − shooterPos
relVel = targetVel − shooterVel
解 |rel + relVel·t| = 弹速·t，取最小正根
瞄准点 = shooterPos + rel + relVel·t
```

早先版本用目标**绝对**速度，漏掉了自己那 30 km/s：150 km 上偏差几度、几十公里，命中率约 1%，双方打到 300 s 都分不出胜负。改成相对速度后同一场景 69 s 结束，关上提前量则打不死。

**口径必须标清：这三个数字（1% / 69 s / 打不死）来自等效二维模型的逐 tick 复算，不是 C# 三维仿真结果，也不是真人试玩。** 原因是本机应用控制策略（0x800711C7）阻止执行新生成的二进制，`CombatSimCli` 只能编译不能跑。换机后要用真实引擎复核这三项，再决定是否采信。[已实现（公式）/ 待实测（数字）]

## 7. 暴露机制

**现状：没有。** 敌舰位置、血量、护盾全程完整显示，开火不产生任何信息代价。[已实现]

设计上给"开火即暴露"做支撑的最小版本（见设计稿第 9 节）：一个 0–1 的信号标量。

| 行为 | 信号 | 消费者 |
| --- | --- | --- |
| 蓄力 / 开火 | +1.0 /s | AI 目标评分 ×(1 + signal)，持续开火的人优先被集火 |
| 停火 | −0.5 /s | 同上，信号低时 AI 有概率放弃追击 |
| signal < 0.2 | — | AI 的交战意愿下降（可脱离） |

只需要一个快照字段 `Signature01`，不需要完整探测系统。[未实现，T11]

两处 v0.3 的设计已删：

- **"锁定距离 ×(1 + 0.3 × signal)"**——AI 不走玩家的 `LockTargetCommand` 通道，这条对它们无效，等于写给空气。
- **"signal ≥ 0.6 时 5 s 内不能主动解除交战"**——对应的静默系统在 Phase 3，玩家现在没有"解除交战"这个动作，规则永远触发不了。没有消费者的机制就是死代码。

## 9. 敌舰 AI

行为清单：找最近的敌方 → 用相对速度解提前量 → 转过去 → 距离超过 0.9 射程就满推、进射程后往 0.7 射程收 → 进射程且进射界就开火。[已实现]

已知缺陷，按影响排序：

| 缺陷 | 影响 | 归属 |
| --- | --- | --- |
| 只打最近目标 | 玩家把护航舰放前面就能当肉盾，AI 不会换目标 | A |
| 不绕后、不利用朝向 | 定向护盾落地后 AI 会显得很蠢 | A |
| 不切能源档 | 敌舰永远均衡档，武器永远不是最快 | A |
| 不用锁定、不控距离以外的东西 | 无法模拟"压制"行为 | A |
| 被绕后没有任何反应 | 包夹对 AI 无成本 | A |
