# 剧情线与任务日志设计

这份文档说明剧情怎么拆成任务、任务怎么进入日志、日志怎么给出导航。它是叙事设计的单一事实来源；`content/` 下的 JSON 是它的可执行数据。两者不一致时，以这份文档为准改配置。

## 一、叙事骨架与第一版范围

小说原文有四阶段矛盾：新兵对抗腐朽联邦 → 无乱星系立国 → 反唐联盟 → 帝制统一宇宙。游戏不一次做完四阶段。

**第一版只做第一阶段的前两章**：唐龙从军、新兵营、第一次实战。范围小是有意的——它刚好覆盖三条要验证的线：战斗手感、关系网的政治选择、资源托管（此时高层代管，玩家只看到作战信息）。后面三阶段写在这里是为了保证任务链的 ID 和前置关系不返工，不做内容。

## 二、三层结构

任务系统拆成三层，各自独立，通过 ID 引用，不互相包含。

| 层 | 数据位置 | 管什么 | 不管什么 |
|---|---|---|---|
| 剧情节点 | `content/stories/*.json` | 对话文本、玩家选择、选择后果 | 不管任务状态、不管导航 |
| 任务条目 | `content/quests/*.json`（新增） | 日志显示、目标分解、前置条件、导航目标 | 不管战斗怎么打、不管对话怎么说 |
| 战斗关卡 | `content/missions/*.json` | 敌我编成、战场环境、胜负条件、奖励 | 不管日志分组、不管剧情文本 |

举例：`quest.first_contact` 引用 `mission.first_contact` 作为执行逻辑，引用 `ch1.after_battle` 作为完成后的剧情入口。任务本身不复制这些内容。

## 三、任务日志（参考《赛博朋克 2077》）

玩家随时能打开任务日志，看到"现在能做什么"和"当前在追哪一个"。这是叙事和星图之间的桥。

### 3.1 分组

任务按 `category` 分三组，日志按固定顺序显示：

- **主线**（`main`）：推动核心剧情，一条时期通常只有一条活跃
- **支线**（`side`）：由关系网或剧情选择派生，比如"站哪一边"
- **委托**（`contract`）：家族势力的资源型任务，或边境势力发布的可重复委托

分组顺序、是否显示已完成任务、同时追踪几条，由 `content/quests/quest-log-view.json` 配置，不写死在代码里。

### 3.2 状态机

```
locked → available → active → completed
                             ↘ failed
```

- `locked`：前置条件未满足，日志里不显示
- `available`：可接但未接，日志里显示，带"可接取"标记
- `active`：进行中，可设为追踪任务
- `completed` / `failed`：按视图配置决定是否显示

状态由运行时根据前置条件和玩家行为计算，配置文件里写的 `status` 只是初始默认值。

### 3.3 目标分解与追踪

一条任务拆成 2–4 个可勾选的小目标，玩家看到的是当前目标（`currentObjectiveId`），不是全部。完成一个目标就推进下一个，全部完成才结算。

追踪任务同时只能有一条。被追踪的任务：

- 日志里置顶
- 星图上高亮目标节点
- HUD 上显示当前目标文字和距离

### 3.4 导航引导

导航数据放在任务条目的 `navigation` 字段里，表现层只消费，不自己算：

- `targetSystemId`：星图节点 ID，星图据此高亮并画航线
- `markerType`：标记类型（`objective` / `npc` / `poi`），决定图标
- `showDistance`：是否显示距离
- `hint`：给玩家的一句话文字引导

星图上的距离显示是显示层的事——按当前缩放动态换算单位，数据源只有一个：星图存的光分坐标。战斗场景里的目标标记同样读这个字段，只是把星图节点换成战场实体。

## 四、任务配置与已有配置的关系

`content/quests/` 新增后，四类配置的职责边界如下：

```
stories/*.json   ──完成后进入──▶  quests/*.json
                                     │
                                     ├──引用──▶ missions/*.json
                                     └──引用──▶ stories/*.json（下一节点）
```

引用一律用 ID，不复制内容。任务条目里的 `rewardsHint` 只是给玩家看的提示文字，实际发多少奖励由 `missions` 和结算工作流决定，避免两处数值打架。

## 五、第一版任务清单

| 任务 ID | 分类 | 作用 |
|---|---|---|
| `quest.first_contact` | 主线 | 新手实战，串联星图移动、战斗、战后剧情 |
| `quest.political_choice` | 支线 | 战后选择站队，改关系值，验证有后果的选择 |
| `quest.imperial_trial` | 主线 | 银鹰阵营示例，验证同一套任务结构能承载不同阵营 |
| `quest.clan_contract` | 委托 | 家族阵营示例，验证资源型任务 |

后两条只做配置示例，不做完整剧情——它们的价值是验证"三阵营共享一套任务系统"这个架构假设，不是凑内容量。
